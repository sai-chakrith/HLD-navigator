# Validation and evaluation procedure

Local checks exercise hand-authored synthetic architecture declarations. They check exact expected entities/locations, no inferred prose relationships, malformed attribute warnings, approval/revocation, individual roles, workspace isolation, token rotation, immutable revision conflicts, atomic failed uploads, transactional rollback, restart persistence, schema compatibility, revision comparison, citation support and unavailable model behavior. The local run on 2026-10-08 with ArchLens's own Python 3.14 environment reports **21 passing tests**, including real generated text/table PDFs, empty-image PDF rejection and a Streamlit initial-load smoke check. One upstream Starlette/httpx deprecation warning remains. These are synthetic checks, not an OEM benchmark. `uv run python tools/smoke.py` independently exercises the live HTTP upload/source-review/entity-review/query/export workflow in a temporary database, then stops the server. Its report is `docs/evidence/live-http.json`. Test output is stored in `docs/evidence/pytest.txt`; lint output in `docs/evidence/lint.txt`.

## External dependencies and acceptance

1. Obtain authorized AUTOSAR HLDs from multiple document families/versions, including scanned pages and architecture diagrams. Preserve file hashes; split by family before tuning.
2. Have two AUTOSAR architects independently label components/interfaces/signals/ports/flows, direction/ownership and declared dependency edges. Label exact source pages/table cells/sections and missing/ambiguous information. Adjudicate disagreements and freeze held-out ground truth.
3. Run ingestion against the held-out documents. Count extraction TP/FP/FN separately by entity and relation type, unsupported-layout rejection rate, missed requirements, and active engineer correction minutes. A parser rejection contributes missed annotations rather than being excluded from the denominator. Repeated evidence locations must be evaluated independently of semantic entity deduplication.
4. Create an architect-reviewed query corpus with relevant passages, correct answers, insufficient evidence, conflicting revisions and injected source instructions. Measure retrieval recall@k/MRR separately from human-reviewed answer relevance/entailment and citation accuracy. Record local model/embedding artifact digests, runtime and failures. This repository's optional model quote gate is not semantic entailment validation.
5. Benchmark manual versus assisted review on matched HLD tasks with counterbalanced participants. Measure active review/correction time, accepted entity/edge proposals, and independently confirmed inconsistencies. Preregister targets; publish observations and sample size. No business benefits have been measured yet.
6. Before non-local deployment, validate IAM/token revocation, TLS, secret-file permissions, role separation, concurrent workloads, backup/restore, audit integrity, extraction resource isolation, malicious PDFs and deployment health. Filesystem administrators can modify this pilot's database/audit; it is not tamper resistant.

## Current limitations

Case Study 1 is only started. No genuine OEM or architect-reviewed holdout, OCR, diagram understanding, learned embeddings, model benchmark, measured engineering pilot or Docker runtime validation is available. The default source-excerpt mode is searchable document evidence, not a synthesized architectural answer. Inventory reports can be incomplete when the source uses unsupported layouts. Unresolved references are candidates for review and may legitimately refer to external components. Structural revision comparison does not prove functional equivalence or perform complete impact analysis.
